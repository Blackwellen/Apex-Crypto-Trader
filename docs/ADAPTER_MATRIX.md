Cross-cutting venue safety code (all pure/injectable, unit-tested): `L2BookSync` (sequence-gap/regression/crossed-book detection, resync-required state, stale gate), `RateLimitManager` (weight budget, 429 exponential backoff + jitter + Retry-After, cooldown, fake-clock tests, non-idempotent calls never auto-retried), `UnknownOrderReconciler` (timeout => UNKNOWN => query by `client_order_id`, never resubmit, absence is not failure), `validateCredentialScope` (rejects any withdrawal/transfer/margin/futures permission, unknown permissions, fail closed) and `redactSecrets`/`redactApiKey`.

**UK availability is UNVERIFIED for every venue.** A human must verify against the venue's own UK terms and FCA material before any UK retail claim: FCA cryptoassets hub https://www.fca.org.uk/firms/cryptoassets and FCA Register https://register.fca.org.uk/s/ . No code or doc here asserts availability.

Verification provenance: each chain record carries `verifiedFrom` (genesis hashes / node network names fetched live on 2026-10-13) and `unverifiedFields`; the lead merges `chainRecords` exported from each `@apex/chain-*` package (and `venueRecords` from `@apex/exchange-adapters`) into the registry.

## Families A (EVM, Solana, Sui, Aptos) -- `@apex/chain-registry`, `chain-evm`, `chain-solana`, `chain-sui`, `chain-aptos`

Test evidence: `docs/evidence/chains-a-tests.md`. Seed migration: `packages/db/migrations/0100_seed_chain_registry.sql` (generated from the TS registry; sync-tested).
